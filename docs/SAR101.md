## 1. ปัญหาที่ SAR แก้

เรดาร์ทำงานโดยยิงคลื่นออกไปแล้วฟังเสียงสะท้อน จับเวลาที่คลื่นใช้เดินทางไปกลับ
ก็จะรู้ระยะทางถึงวัตถุ

```
ระยะ R = c · t / 2          (c = ความเร็วแสง, t = เวลาไป-กลับ, หาร 2 เพราะไปแล้วกลับ)
```

**ปัญหาคือทิศทาง** — เรดาร์รู้ว่ามีของอยู่ห่างออกไป 1 กม. แต่ไม่รู้ว่าอยู่ซ้ายหรือขวา
ความละเอียดในแนวขวาง (cross-range) ของสายอากาศจริงคือ

```
มุมลำคลื่น  θ ≈ λ / D        (λ = ความยาวคลื่น, D = ขนาดสายอากาศ)
```

ที่ 4 GHz (λ = 7.5 ซม.) สายอากาศยาว 4 ม. ให้มุมลำคลื่นประมาณ 1° ซึ่งที่ระยะ 1 กม.
แปลว่าแยกของสองชิ้นที่ห่างกันน้อยกว่า **~17 ม.** ไม่ออกเลย ถ้าอยากได้ 0.1 ม.
ต้องใช้สายอากาศยาวเป็นหลายร้อยเมตร — ติดบนเครื่องบินไม่ได้

**ทางออกของ SAR** — ถ้าเอาสายอากาศใหญ่ไปติดเครื่องบินไม่ได้ ก็ใช้สายอากาศเล็ก
แล้ว**บินผ่านฉาก** ยิงพัลส์ไปเรื่อย ๆ ระหว่างทาง จากนั้นเอา echo ทุกพัลส์มาประกอบกัน
ทางคณิตศาสตร์ — เสมือนว่าเรามีสายอากาศยาวเท่ากับระยะทางที่บินไป

นั่นคือที่มาของชื่อ **Synthetic Aperture** = ช่องรับสังเคราะห์

> aperture ยาว 400 ม. ที่ระยะ 1 กม. → cross-range ~0.1 ม. ดีขึ้นจากเดิม 170 เท่า
> โดยไม่ต้องเปลี่ยนฮาร์ดแวร์เลย แค่บินแล้วคำนวณให้ถูก

## 2. Pipeline 3 ขั้น

โค้ดในโฟลเดอร์ `01_point_target/` ทำครบทั้ง 3 ขั้นนี้ในไฟล์เดียว อ่านไฟล์นั้นควบไปด้วยได้

### ขั้น 1 — สร้าง (หรือรับ) raw echo

เรดาร์ไม่ได้ยิงพัลส์สั้น ๆ ทื่อ ๆ เพราะพัลส์สั้นต้องใช้กำลังสูงมาก
แทนที่จะทำแบบนั้น เรดาร์ยิง **LFM chirp** — คลื่นยาว ๆ ที่ความถี่ไล่ขึ้นเรื่อย ๆ ระหว่างพัลส์

```
s(t) = exp( j·π·K·t² )        K = B / Tp  (อัตราไล่ความถี่, Hz/s)
```

echo ที่ได้กลับมาเป็น matrix 2 มิติ: **fast time × slow time**

| แกน | คือ | ในโค้ด |
|---|---|---|
| fast time (แถว) | เวลาภายในพัลส์เดียว → แปลงเป็นระยะได้ | `rxsig(:, n)` |
| slow time (คอลัมน์) | ลำดับพัลส์ = ตำแหน่งเครื่องบิน | `rxsig(:, n)` โดย n = pulse |

ภาพ raw echo จะเห็นเป็น**เส้นโค้งไฮเพอร์โบลา** — เพราะระยะจากเครื่องบินถึงเป้าใกล้สุด
ตอนบินผ่านตรง ๆ และไกลขึ้นทั้งก่อนและหลัง เรียกปรากฏการณ์นี้ว่า *range migration*

### ขั้น 2 — Range compression

บีบ chirp ยาว ๆ ให้กลายเป็นยอดแหลม ๆ ด้วย **matched filter** = สหสัมพันธ์ echo
กับ chirp ที่ยิงออกไป (คอนจูเกตเชิงซ้อนกลับด้าน)

```matlab
mf   = conj(flipud(chirp));      % matched filter
rc   = conv(rxsig, mf);          % หรือทำใน frequency domain ให้เร็วกว่า
```

หลังขั้นนี้ ความละเอียดในแนวระยะจะได้ตามทฤษฎีคือ `c/(2B)` ทันที
ไฮเพอร์โบลาที่เคยเบลอกว้างจะกลายเป็นเส้นคมบาง — แต่**ยังไม่โฟกัสในแนวขวาง**

### ขั้น 3 — Backprojection (BP)

นี่คือหัวใจ แนวคิดตรงไปตรงมามาก:

> สำหรับทุกพิกเซลในภาพ ให้ถามว่า *"ถ้ามีเป้าอยู่ตรงนี้จริง เรดาร์จะเห็นสัญญาณอะไร?"*
> แล้วไปดึงค่านั้นจากข้อมูลจริงมาบวกสะสม — ถ้าตรงนั้นมีของจริง ค่าจากทุกพัลส์จะบวกเสริมกัน
> ถ้าไม่มี ค่าจะสุ่มเฟสแล้วหักล้างกันเอง

```
สำหรับทุกพิกเซล p:
    สำหรับทุกพัลส์ n:
        R = ระยะจากตำแหน่งเรดาร์(n) ถึงพิกเซล p
        ดึงค่าจาก rc ที่ตำแหน่ง R  (ต้อง interpolate เพราะไม่ลงตัวพอดี)
        คูณ phase correction: × exp(j·4π·fc·R/c)
        บวกสะสม
```

`4π` มาจากการเดินทางไป-กลับ (2 × 2π) การคูณเฟสนี้คือสิ่งที่ทำให้การรวมเป็นแบบ
**coherent** — ถ้าลืมขั้นนี้ ภาพจะเบลอทันที

**BP ช้าแต่ยืดหยุ่นที่สุด** เพราะไม่ได้ตั้งสมมติฐานเรื่องเส้นทางบินเลย บินโค้ง บินวน
บินหลายระดับ ก็ใช้สูตรเดียวกัน — ซึ่งเป็นเหตุผลที่ repo นี้ใช้ BP ตลอดตั้งแต่ต้นจนจบ

> **ทางเลือกที่เร็วกว่า** — Range-Doppler Algorithm (RDA) ทำงานใน frequency domain
> เร็วกว่า BP ประมาณ 40 เท่า แต่ต้องสมมติว่าบินเป็นเส้นตรง
> `02_box_2d/box_compare_rda_density.m` เทียบสองวิธีนี้ไว้ — **ได้ resolution เท่ากัน**
> ซึ่งพิสูจน์ว่าอัลกอริทึมไม่ได้เปลี่ยนความคมของเรดาร์ มันเปลี่ยนแค่ความเร็วกับ sidelobe

## 3. หลักการเดียวที่คุมทุก resolution

ถ้าจะจำอะไรจากเอกสารนี้แค่อย่างเดียว ให้จำอันนี้:

> **ความละเอียดในทิศทางใดก็ตาม ≈ λ / (2 × มุมที่ aperture กวาดได้ในทิศนั้น)**
>
> ```
> δ ≈ λ / (2 · Δθ)
> ```
>
> ยกเว้นแนวระยะ (range) ที่มาจากแบนด์วิดท์เป็นหลัก: `δr ≈ c / (2B)`

รูปข้างบนเป็นค่าประมาณที่ใช้ได้เมื่อ aperture แคบ — ถ้า aperture กว้างจนทิศที่มอง
เปลี่ยนไปมาก ต้องใช้รูปเต็มใน [หัวข้อ 3.1](#31-สูตรข้างบนเป็นค่าประมาณ-ของจริงขึ้นกับเรขาคณิตด้วย)

สามมิติ สามที่มา — และนี่คือเหตุผลว่าทำไมบางมิติวัดได้ บางมิติวัดไม่ได้

| มิติ | สูตรที่เจอในตำรา | ขึ้นกับ | เพิ่มความคมยังไง |
|---|---|---|---|
| **Range** (แนวระยะ) | `δr = c/(2B)` | แบนด์วิดท์เป็นหลัก | เพิ่ม bandwidth — **เปลี่ยนความถี่กลางไม่ช่วย** |
| **Cross-range** (แนวขวาง) | `δx ≈ λ/(2·Δθ_az)` | มุม azimuth ที่บินกวาด | บินไกลขึ้น / วนรอบ / ใช้ความถี่สูงขึ้น |
| **Height** (แนวสูง) | `δz ≈ λ/(2·Δθ_el)` | มุม elevation ที่ pass กระจาย | บินซ้ำหลายระดับให้ห่างกันมากขึ้น |

`Δθ_el` แปลงจากระยะห่างแนวตั้งของเส้นทางบิน (elevation baseline `B⊥`) ได้ด้วย
`Δθ_el ≈ B⊥ / R` ซึ่งพอแทนกลับเข้าไปจะได้รูปที่เจอบ่อยในตำรา: `δz ≈ λR/(2·B⊥)`

### 3.1 สูตรข้างบนเป็นค่าประมาณ — ของจริงขึ้นกับเรขาคณิตด้วย

สูตรในตารางใช้ **ระยะบนพื้น `R`** และสมมติว่ามุมมองไม่เปลี่ยนระหว่างบิน
ในภาพที่โฟกัสด้วย backprojection จริง ๆ ทั้งสองอย่างไม่จริง เพราะ

1. เรดาร์อยู่สูงกว่าพื้น จึงมองเฉียงลงมา — ระยะจริงคือ **ระยะเอียง `ρ`** ไม่ใช่ `R`
2. ตลอด aperture ทิศที่มองเปลี่ยนไปเรื่อย ๆ — ข้อมูลจึงเติมเต็มบริเวณที่กว้างกว่าการมองทิศเดียว

รูปเต็มที่ตรงกับสิ่งที่วัดได้จริง

```
แนว range        δr = c / ( 2 · [ f₂·cos ψ₀ − f₁·cos ψmax ] )
แนว cross-range  δx = 0.886 · λmin · ρmax / ( 2L )
```

| สัญลักษณ์ | คือ |
|---|---|
| `f₁, f₂` | ขอบล่างและขอบบนของแบนด์วิดท์ (`fc ∓ B/2`) |
| `λmin` | ความยาวคลื่นสั้นสุดในแบนด์ = `c/f₂` |
| `ρ` | ระยะเอียงจากเรดาร์ถึงเป้า · `cos ψ = R/ρ` |
| `ψ₀` | ตอนอยู่ broadside (ρ สั้นสุด) · `ψmax` ตอนอยู่ปลาย aperture (ρ ยาวสุด) |
| `L` | ความยาว aperture |
| `0.886` | แฟกเตอร์ความกว้าง −3 dB ของ aperture ที่ถ่วงน้ำหนักสม่ำเสมอ |

**ตรวจกับผลรันจริงของ `01_point_target/` (aperture 400 m, บินสูง 500 m)**

| เป้า | δr วัดได้ | δr จากสูตร | δx วัดได้ | δx จากสูตร | δx จาก `λR/2L` |
|---|---|---|---|---|---|
| T1  R = 800 m | 1.5085 m | 1.5457 m | 0.0785 m | **0.0796 m** | 0.0749 m |
| T2  R = 1000 m | 1.7372 m | 1.8513 m | 0.0938 m | **0.0937 m** | 0.0937 m |
| T3  R = 1300 m | 2.1480 m | 2.2181 m | 0.1167 m | **0.1161 m** | 0.1218 m |

สังเกตคอลัมน์สุดท้าย — สูตรในตำราคลาด **−4.6% / −0.1% / +4.4%** ซึ่งไม่ใช่ความคลาดเคลื่อนสุ่ม
แต่เป็นแนวโน้มเป็นระบบที่หายไปเมื่อเปลี่ยน `R` เป็น `ρmax` และใช้ `λ` ที่ `f₂`

> **จุดที่คนพลาดบ่อย** — `c/2B` คือ resolution ของพัลส์ที่ผ่าน range compression แล้ว
> วัดตามแนวสายตา ไม่ใช่ resolution ของภาพ 2 มิติที่โฟกัสแล้ว ในโปรเจกต์นี้ค่าจริง
> อยู่ที่ **1.51–2.15 m** ไม่ใช่ 3.00 m เพราะการรวมข้ามมุม 17–28° ขยาย support
> ในแนว range ด้วย ไม่ใช่แค่แนว cross-range

**ตรวจกับตัวเลขของ GOTCHA (aperture 4° ต่อ subaperture — แคบพอที่สูตรตำราจะใช้ได้)**

| | คำนวณ | ได้ | ที่รายงานไว้ |
|---|---|---|---|
| range, GOTCHA | `3e8/(2·624e6)` | 0.24 m | 0.24 m ✓ |
| cross, GOTCHA | `0.0312/(2·0.0698)` — Δθ = 4° | 0.224 m | 0.22 m ✓ |
| height, GOTCHA | `0.0312/(2·0.0293)` — Δθ = 1.68° | 0.533 m | 0.53 m ✓ |
| height, sim | Δθ_el = 20 m baseline ที่ ρ = 1118 m | 2.62 m | ทฤษฎี 2.6 m ✓ |

> ในโค้ด `03_box_3d/box_tomography_multipass.m` เขียนสูตรความสูงเต็มรูปเป็น
> `dz_res = λ·r0 / (2·B_elev·cos²θ)` — ตัว `cos²θ` คือการฉาย baseline แนวตั้ง
> ให้ตั้งฉากกับแนวสายตา (θ = มุมกดจากแนวราบ) เป็นรูปเดียวกับ `λ/(2Δθ)` แค่เขียนละเอียดกว่า

### ทำไมเรื่องนี้ถึงสำคัญกับผลของโปรเจกต์

GOTCHA มี 8 pass กระจายอยู่ในมุม elevation แค่ **~1.7–2.65°** ซึ่งเป็น aperture
ที่บางมาก ผลคือ:

- ความละเอียดแนวสูงได้แค่ ~0.5–0.75 ม.
- แต่รถเก๋งในฉากสูงต่างกันแค่ 0.10–0.13 ม. → **น้อยกว่า 1 voxel**
- ซ้ำร้าย aperture ที่บางและไม่สม่ำเสมอทำให้ **sidelobe สูงถึง −8.9 dB** (ปกติควรต่ำกว่า −13 dB)
  ซึ่งสูงกว่าเกณฑ์วัดที่ใช้ (−20 dB) มาก → ทุกจุดสร้าง "สำเนาปลอม" เหนือตัวเอง

นี่คือเหตุผลทั้งหมดว่าทำไมโปรเจกต์นี้วัดความกว้างรถได้แม่นระดับเซนติเมตร แต่วัดความสูงไม่ได้เลย
— ไม่ใช่เพราะโค้ดผิด แต่เพราะ **aperture ไม่พอ** และเป็นข้อจำกัดที่ AFRL เองก็ระบุไว้ในเอกสาร
challenge ว่าเป็นโจทย์วิจัยที่ยังเปิดอยู่

## 4. ตารางพารามิเตอร์

### 4.1 พารามิเตอร์เรดาร์

| พารามิเตอร์ | ตัวแปรในโค้ด | sim (`01_`–`03_`) | GOTCHA (`04_`) | คุมอะไร |
|---|---|---|---|---|
| ความถี่กลาง | `fc` | 4 GHz (C-band) | 9.6 GHz (X-band) | λ → cross & height res |
| ความยาวคลื่น | `lambda` | 7.49 ซม. | 3.12 ซม. | ยิ่งสั้น ยิ่งคมในแนวขวาง/สูง |
| แบนด์วิดท์ | `bw` | 50 MHz | 624 MHz | **range res เท่านั้น** |
| ความยาวพัลส์ | `tpd` | 3 µs | — | พลังงานต่อพัลส์ |
| อัตราสุ่ม | `fs` | 120 MHz | — | ต้อง ≥ bandwidth |
| อัตราซ้ำพัลส์ | `prf` | 1000 Hz | — | จำนวนตัวอย่างในแนวขวาง |
| ขนาดสายอากาศ | `aperture` | 4 ม. | — | ความกว้างลำคลื่น |

> GOTCHA ไม่มีช่อง `tpd` / `fs` / `prf` เพราะข้อมูลที่ปล่อยมาเป็น **phase history ใน
> frequency domain** อยู่แล้ว (matrix `fp` ขนาด freq × pulse) ไม่ใช่สัญญาณดิบตามเวลา
> — ขั้น range compression จึงทำด้วย IFFT ตามแกนความถี่ ไม่ต้องสร้าง matched filter เอง

| ระยะถึงฉาก (พื้น) | `groundR0` | 1000 ม. | ~10.2 กม. | ขนาด footprint |
| ความเร็ว | `speed` | 100 ม./วิ | — | ความยาว aperture ต่อเวลา |
| เวลาเก็บข้อมูล | `flightDuration` | 4 วิ | — | |
| ความยาว aperture | — | 400 ม. (≈20°) | 4°/subaperture, 360° เต็มวง | **cross-range res** |
| จำนวน pass แนวสูง | `Npass` | 21 | 8 | จำนวนตัวอย่างแนวสูง |
| ระยะห่างระหว่าง pass | `dzPass` | 1.0 ม. | ไม่สม่ำเสมอ (ช่องว่าง 0.39°/0.52°) | ambiguity แนวสูง |
| Elevation baseline | `B_elev` | 20 ม. (≈1.03°) | ~300 ม. (1.68°) | **height res** |

### 4.3 พารามิเตอร์ของเป้าจำลอง (`02_`, `03_`)

| พารามิเตอร์ | ค่า | หมายเหตุ |
|---|---|---|
| ขนาดกล่อง | 30 × 20 × 10 ม. | range × cross × สูง |
| จุด scatterer | 216 (6 หน้า × 36) หรือ 20×20/หน้าในรุ่นหนาแน่น | |
| RCS ต่อหน้า (สัปดาห์ 5) | `[2.0 0.5 1.0 1.0 0.8 0.3]` m² | **ตั้งเอง** ไม่ได้อิงฟิสิกส์ |
| RCS ต่อหน้า (สัปดาห์ 6+) | `σ = 4πA²/λ²` | สูตรแผ่นเรียบ — ค่าใหญ่มาก (10⁶–10⁸ m²) |

> **ค่าสัมบูรณ์ของ RCS ไม่สำคัญ** — มันตัดกันไปในภาพที่ normalize แล้ว
> สิ่งที่เปลี่ยนภาพจริง ๆ คือ**ลำดับความสว่างระหว่างหน้า** เท่านั้น
>
> `σ = 4πA²/λ²` เป็นค่า **broadside maximum** — ตกลงเร็วมากเมื่อมองเฉียงออกจากแนวตั้งฉาก
> นี่คือเหตุผลที่บินฝั่งเดียวเห็นผนังไม่ครบ ต้องบินหลายทิศ (multi-aspect / circular)

### 4.4 พารามิเตอร์ sparse 3D reconstruction (`04_`)

ชุดนี้ผ่านการทดลองหาค่ามาแล้ว **เปลี่ยนแล้วผลจะไม่ตรงกับที่รายงาน**

| ตัวแปร | ค่า | ทำไมค่านี้ |
|---|---|---|
| `NsigCFAR` | 30 | เกณฑ์ตัดของ FISTA คิดเป็นกี่เท่าของ σ ของ noise — ต่ำกว่านี้เหลือ "หมอก" |
| `nIterFISTA` | 200 | น้อยกว่านี้ L1 แยก ghost แฝดไม่ทัน |
| `gateRng` | 3.5 ม. | ประตูคัดในแนวระยะรอบเป้า |
| `gateCrs` | 4.5 ม. | ประตูคัดในแนวขวาง — กว้างกว่านี้รถคันข้าง ๆ wrap เข้ามา |
| `subApWidth` | 5° | ความกว้าง subaperture ตามเปเปอร์ |
| `topDB` | 40 | ช่วง dB ที่แสดงผล ตามเปเปอร์ |
| `relFloor` | 0.02 | พื้น threshold สัมพัทธ์กับยอด |
| grid | 100³ @ 0.10 ม. | ตามเปเปอร์ |

> **ทำไมต้อง sparse (L1) ไม่ใช่ Fourier ธรรมดา** — 8 pass = ตัวอย่างแค่ 8 เส้นในแนว elevation
> และห่างไม่เท่ากัน k-space จึงบางและมีรู การทำ FFT ตรง ๆ กับข้อมูลแบบนี้ให้ภาพเบลอเป็น
> "นาฬิกาทราย" ในแนวสูง การเพิ่มเงื่อนไขว่า *"ฉากประกอบด้วยจุดสะท้อนไม่กี่จุด"* (sparsity)
> เข้าไปในการแก้สมการ คือสิ่งที่ทำให้ได้ความละเอียดแนวสูงที่ใช้งานได้จากข้อมูลเท่าเดิม
>
> เทียบกันตรง ๆ อยู่ใน `04_gotcha_real/main/gotcha_sparse3d_showcase.m`

## 5. ทำไมภาพ 2 มิติทำความสูงหาย

เรดาร์วัดได้แค่ **ระยะ** ไม่ได้วัดมุมกด จุดที่อยู่สูงกับจุดที่อยู่บนพื้นแต่ใกล้เรดาร์กว่า
อาจมีระยะเท่ากันพอดี → ตกลงมาที่พิกเซลเดียวกันในภาพ 2 มิติ

เรียกว่า **layover** — และเป็นเหตุผลว่าทำไมตึกในภาพ SAR ดู "ล้มทับ" มาทางเรดาร์

```
จุดที่ความสูง h  จะปรากฏในภาพ 2 มิติเลื่อนเข้าหาเรดาร์เป็นระยะ  h · tanθ
```

**วิธีกู้ความสูงกลับมา มี 2 ทาง**

1. **สร้าง elevation aperture** — บินซ้ำหลายระดับความสูง แล้วรวมแบบ coherent
   (tomography) นี่คือทางที่โปรเจกต์นี้ใช้เป็นหลัก ทำใน `03_box_3d/` และ `04_gotcha_real/`
   *ข้อจำกัด:* ต้องมี pass เยอะและกระจายกว้างพอ — GOTCHA มีแค่ 8 pass ใน 1.7° จึงติดเพดาน

2. **ใช้ layover เป็นเบาะแส** — พอบินวนรอบเป้า จุดที่สูงจะกวาดเป็นวงกลมในภาพ
   ส่วนจุดบนพื้นอยู่นิ่ง ถ้า "โหวต" ย้อนกลับได้ก็จะรู้ความสูงโดย**ไม่ต้องพึ่ง elevation
   aperture เลย** — **ลองแล้ว 3 รอบแต่ยังไม่สำเร็จ** ตัวกรองกำจัดยอดปลอมได้ และอ่านเป้าสอบเทียบ
   tophat ได้ ~1.15 m แต่อ่านค่ารถยังไม่ได้ จึงไม่ได้เอาโค้ดส่วนนี้ขึ้น repo
   รายละเอียดอยู่ในภาคผนวกของ `docs/GOTCHA_Writeup.pdf`

## 6. ศัพท์ที่เจอบ่อยในโค้ด

| ศัพท์ | แปล / หมายถึง |
|---|---|
| **fast time / slow time** | เวลาภายในพัลส์ (→ ระยะ) / ลำดับพัลส์ (→ ตำแหน่งเครื่องบิน) |
| **slant range** | ระยะตรงจากเรดาร์ถึงเป้า (เส้นเฉียง) — ต่างจาก ground range ที่วัดบนพื้น |
| **phase history** | ข้อมูลดิบก่อนสร้างภาพ ในรูป frequency × pulse (ตัวแปร `fp` ของ GOTCHA) |
| **range compression** | บีบ chirp ยาวให้เป็นยอดแหลม ด้วย matched filter |
| **range migration** | ปรากฏการณ์ที่ระยะถึงเป้าเปลี่ยนไปตามการบิน → echo เป็นเส้นโค้ง |
| **coherent / incoherent** | รวมโดยคิดเฟสด้วย (โฟกัสได้) / รวมแค่ขนาด (ไม่โฟกัส แต่ลด speckle) |
| **backprojection (BP)** | สร้างภาพโดยไล่ถามทีละพิกเซลว่า "ถ้ามีของตรงนี้จะเห็นอะไร" |
| **voxel** | พิกเซลใน 3 มิติ |
| **PSF / IRF** | หน้าตาที่เป้าจุดเดียวปรากฏในภาพ — ใช้วัดความคมจริงของระบบ |
| **sidelobe** | ยอดข้างเคียงที่โผล่ข้าง ๆ ยอดหลัก — ถ้าสูงเกินไปจะกลบเป้าจริงที่จาง |
| **PSLR** | อัตราส่วนยอดข้างต่อยอดหลัก (dB) ยิ่งต่ำยิ่งดี — ในอุดมคติต่ำกว่า −13 dB |
| **taper / window** | คูณน้ำหนักก่อน FFT เพื่อกด sidelobe แลกกับ mainlobe กว้างขึ้น (โค้ดใช้ Taylor −35 dB) |
| **RCS** (σ) | หน้าตัดสะท้อนเรดาร์ — ว่าเป้าสะท้อนกลับมาแรงแค่ไหน หน่วย m² |
| **specular / glint** | การสะท้อนแบบกระจก — แรงมากเฉพาะมุมตั้งฉาก หลุดมุมแล้วหายเลย |
| **occlusion** | หน้าที่เรดาร์มองไม่เห็น (ด้านไกล / ด้านที่วางบนพื้น) ต้องตัดออกจากโมเดล |
| **speckle** | ลายจุดคล้ายสัญญาณรบกวน เกิดจากจุดสะท้อนย่อยในเซลล์เดียวกันแทรกสอดกัน |
| **multilook** | เฉลี่ยหลายมุมมองเพื่อลด speckle แลกกับความละเอียดที่หยาบลง |
| **subaperture** | ตัด aperture ยาวเป็นชิ้นสั้น ๆ (โปรเจกต์นี้ใช้ 5°) เพื่อประมวลผลทีละชิ้น |
| **layover** | จุดสูงกับจุดพื้นตกที่พิกเซลเดียวกันเพราะระยะเท่ากัน |
| **autofocus** | แก้ error การเคลื่อนที่ของเครื่องบินที่ทำให้ภาพเบลอ (GOTCHA แนบค่ามาให้แล้วใน `af`) |
| **corner reflector / tophat** | เป้าสอบเทียบที่รู้ตำแหน่งและขนาดแน่นอน ใช้เป็นไม้บรรทัด |
| **ghost** | สำเนาปลอมของเป้าจริงที่โผล่ผิดที่ ในโปรเจกต์นี้เกิดจาก elevation sidelobe |
| **CFAR** | วิธีตั้งเกณฑ์ตัดโดยอิงระดับ noise รอบ ๆ ไม่ใช่อิงยอดสูงสุด |
| **FISTA** | อัลกอริทึมแก้สมการ L1 แบบวนซ้ำ ใช้ใน sparse 3D reconstruction |
